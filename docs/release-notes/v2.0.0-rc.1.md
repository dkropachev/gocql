# gocql v2.0.0-rc.1 (draft)

Draft notes for the first v2 release candidate. The Release workflow publishes
GitHub's generated notes (see `RELEASING.md`), which list merged pull requests
only. Once the release is published, add this text above them in the GitHub
Release description, and update it for later candidates.

v2 is a new major version with a new module path,
`github.com/scylladb/gocql/v2`, and a typed API for ScyllaDB and Apache
Cassandra. It is not source compatible with v1. Both versions can be imported
by one program, so applications can migrate one package at a time; the
[migration guide](https://github.com/scylladb/gocql/blob/v2.0.0-rc.1/docs/source/migrating-from-v1.md)
maps the most used v1 calls to v2.

```sh
go get github.com/scylladb/gocql/v2@v2.0.0-rc.1
```

This is a release candidate. The API may still change before v2.0.0 if
testing finds a problem; report issues at
https://github.com/scylladb/gocql/issues.

## Highlights

- **Typed statements.** A `cql.Statement[P, R]` declares its parameter and row
  types with explicit encoders and decoders, or with struct mappings
  (`cql.ParamsOf`, `cql.RowOf`) built once and checked against the server's
  metadata at prepare time. No per-call reflection.
- **Low-allocation execution.** `Prepared.Exec`, `One`, `Each` and `All` run a
  shared prepared statement with no per-call execution state, and a
  worker-owned `Query` reuses its parameter buffers and resolved options.
- **Streaming into caller storage.** `Session.PrepareStream` decodes rows into
  storage the caller seeds, page by page or incrementally with bounded memory
  (`exec.StreamOptions{Incremental: true}`).
- **Shard- and tablet-aware routing on ScyllaDB.** One connection per shard,
  shard-aware ports, tablet routing, and optional leader-aware routing for
  strongly consistent tables, behind one `routing.Policy`.
- **Validated configuration.** `config.New(...).Build()` checks every setting
  and returns an immutable `config.Config`; request defaults live in
  `config.Profile`, per-call overrides in `exec.Options`.
- **Errors that say what happened.** Typed server errors in `cqlerr`,
  `cqlerr.KindOf` to tell transient failures from permanent ones, and
  `cqlerr.ExecutionStatusOf` to tell whether a failed write may have applied.
  `retry.Safe` retries a non-idempotent request only after a failure that
  reports it was not executed.
- **Observation.** `observe` hooks per request and per attempt, `metrics`
  snapshots, `log/slog` logging, `cqltrace` for server-side traces, and
  `Session.Subscribe` for topology, status and schema events.

## Breaking changes from v1

Every v1 call site changes. In short:

- Module path `github.com/scylladb/gocql/v2`; Go 1.27 or newer.
- `gocql.NewCluster` and `ClusterConfig` fields are replaced by the
  `config.New(...)` builder; `CreateSession` by
  `gocql.Connect(ctx, cfg, dialect)`.
- The dialect (`gocql.ScyllaV4`, `gocql.CassandraV4`, `gocql.CassandraV5`)
  fixes the database and protocol version; nothing is negotiated, and
  protocols 3 and older are not supported.
- `session.Query(stmt, values...)` with `Scan`/`Iter` is replaced by typed
  statements, explicit `Session.Prepare`, and
  `Exec`/`One`/`Each`/`All`/`Run`/`RunPage`.
  Every call takes a `context.Context` first.
- Per-query setters (`Consistency`, `PageSize`, `Idempotent`, ...) become
  `exec.Options` fields; cluster-wide request defaults become a
  `config.Profile`.
- Host selection, retry and speculative execution policies are replaced by
  `routing.Policy`, `retry.Policy` and `retry.SpeculationPolicy`.
- Errors move to `cqlerr`; `gocql.ErrNotFound` from `Scan` becomes the `found`
  result of `One`.
- The default consistency is `LOCAL_QUORUM` (v1: `QUORUM`).
- `USE` statements are rejected; set the keyspace in the configuration.
- `Marshaler`/`Unmarshaler` are replaced by `cql.Encoder`/`cql.Decoder` codecs.

## Known limitations

- Protocol 4 frame compression (LZ4 or Snappy) cannot be combined with
  incremental streaming; such a query fails with `cql.StreamCapabilityError`
  before it is sent. Buffered execution supports it.
- `cql.PageState` tokens are opaque server state and are not signed by the
  driver; authenticate or encrypt them before handing them to untrusted
  clients.
- ScyllaDB-only features (tablets, shard awareness, rate-limit errors, the
  CDC partitioner) have no effect on Cassandra. Settings that only one dialect
  supports, such as `WithClientRoutes` or `exec.Options.NowInSeconds`, fail at
  `Connect` or `CompileOptions` on the other dialect; see
  [server differences](https://github.com/scylladb/gocql/blob/v2.0.0-rc.1/docs/source/server-differences.md).
- Cassandra and ScyllaDB return different rows for conditional statements and
  batches; decode them as the
  [lightweight transactions guide](https://github.com/scylladb/gocql/blob/v2.0.0-rc.1/docs/source/statements/lightweight-transactions.md)
  describes.
